# M4 — Data trust and verification

Status: **NOT STARTED**
Dependency: M1 lifecycle and M2 schema

## Objective

Let users judge the provenance, freshness, verification, and correction history
of every opportunity.

## Planned scope

- Verification states: discovered, extracted, needs review, approved, published,
  rejected.
- Method, verifier, confidence, evidence, official URL, last checked, and source
  tier fields.
- A/B/C/D official-source quality tiers.
- Field evidence for deadlines, identifiers, organisations, qualifications,
  value/EMD, vacancies, and official links.
- Manual review UI/audit trail, issue-report flow, link checks, correction audit.
- Quality sampling for duplicates, deadlines, links, leakage, classification,
  and verification distribution.
- Copyright-safe metadata/link handling for newspapers and documents.

## Exit criteria

- Uncertain OCR/AI records cannot appear fully verified.
- Verification and official-source state are visible.
- Accuracy thresholds and duplicate rate are measured.
- Users can report issues and corrections are auditable.
